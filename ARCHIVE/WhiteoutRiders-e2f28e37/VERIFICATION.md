# Verification

The automated suite drives with throttle, steering, drift and boost for **180 seconds of wall time**. The autopilot writes the same key states as keyboard controls; initial throttle and garage purchases use browser events. It follows actual terrain to beacon starts and destinations; main-loop job rewards and the first upgrade use earned currency, with no teleport or currency injection. The separate post-run debug smoke uses teleport to force quick-rescue completion and test retry, and positions a sled at a fence to assert destruction. This is not a full manual playtest of every rescue route.

Screenshots are generated by `npm test` in ignored `test-output/` at load, 30 seconds, 180 seconds, and the first earned engine upgrade (plus an equipped-sled view). The test server exposes dev access only under `/dev/`; the production build has no hook, teleport switch, currency helper or FPS UI. The suite checks both the production script and browser global.

The source's dense curling spray, natural fir branching and photoreal detail are not matched. The implementation uses procedural meshes, bounded powder instances, moving snow flecks and exponential fog. Low mode further reduces forest detail and render resolution.

## Limits

No manual integrated-GPU 60 fps certification, controller hardware test, touch-device test, audio listening test, or 30-minute economy balance test was performed. The software-rendered headless result is reported as measured, not as hardware performance. At very low render rates the physics timestep cap slows simulation relative to wall time. The three-minute test therefore reports both wall time and the final simulation clock.
